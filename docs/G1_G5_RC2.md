# Invest 0.2.0-rc2：G1–G5 集成修复与交付

本版接续 `519f30b09bc8a6addc4db038addf48c9cf203b4f` 的离线工作台。代码权威为 **Jvust/Invest**（稳定仓库 ID 1381007406），工作分支 `feat/g1-g5-workbench-20260926`，Draft PR #4，基于研究分支，未合并到 main。

## 本次已做的改进

**修复实际 Windows 包的代码身份缺陷。** 上一版 CI run `36252240721` 的 Windows 235 项测试、22 项真实浏览器检查确实通过。但实际 EXE 导出的 `browser-synthetic-study.json` 中 `code_identity` 是 SHA256(`{}`)：打包程序不再包含可被 glob 找到的散装 Python 源码，旧函数却把空集合当成有效身份。原算术测试仍是历史事实，但该身份不能证明具体源码版本；本版不篡改旧研究记录或旧包补造来源。

新增 `invest/provenance.py`：源码模式按 UTF-8/LF 规范化完整 Python 核心；构建时生成带 source commit 的非空清单，随便携包放入 `_internal/invest/build_identity.json`。运行于 EXE 时缺失、损坏、空清单或缺核心模块均明确报错。Windows 流程必须比对 **实际 EXE 经 HTTP 导出的研究身份** 和构建源码身份，不以源码测试代替成品测试。

**修复满额幂等。** 复盘账户达到 10,000 条事件时，同键同内容的成功操作重试返回原事件；新事件仍拒绝，同键异内容仍明确冲突，避免误以为失败后再次录入。

**修复备份容量不一致。** 导出同时校验两个 SQLite 数据库、清单的总解压大小及压缩包大小，不再产生恢复函数必然拒绝的超限包。恢复仍只建立新目录，不覆盖已有私人数据。

**修复开发/发布入口。** 打包与浏览器脚本导入时不再读取命令行参数、环境字段或启动进程。pytest 默认只收集正式测试目录；实际 Windows 流程仍独立运行浏览器脚本。构建拒绝已修改的已跟踪源码，以及缺失或未跟踪的 Python 核心文件。

## 可运行能力与验收边界

| 成长级 | 当前可运行能力 | 尚未具备的现实验收证据 |

| G2 | 有界均线假设比较、共同评价窗口、3 个成本情景、失败留存、未来数据扰动测试、独立算术回放 | 3 种真实市场环境、第二个独立成交引擎、未见留出验证 |
| G3 | 历史模拟及人工复盘、现金流/股息/费用、完整估值、事件哈希链、并发/重试保护 | 冻结协议下持续真实前向观察；历史补录不算已运行天数 |

这不是独立第三方审阅。rc2 Windows 构建和浏览器是否通过，必须看 **rc2 对应源提交** 的 Actions 和后续 `governance/growth_delivery_result.json`；不能借用 rc1 Windows 证据。证据包包含源测试、native-smoke、browser、build_identity、packaged-code-identity 以及实际截图。

源码身份清单是构建声明，不是硬件签名、运行时字节码签名或第三方见证。Python 核心身份不单独覆盖 UI 或依赖；完整便携包由 PACKAGE_MANIFEST 另行逐文件列示，依赖版本记录于构建证据。任何哈希都不证明数据真实、许可有效或投资收益。

## 使用与升级

解压整个便携包后启动 `Invest.exe`，保留 `_internal`。先用“载入合成演示”核对界面。新版与旧版采用不同应用目录；旧账本先导出完整备份，保留原数据，不自动删除或重写历史。

源码启动：`python -m invest --data-dir D:\Invest-Data --open`。测试：`python -m pytest -q` 或 `python -m unittest discover -s tests -v`。核心不需要美元、GPU、模型 API；真实数据仍须按现有来源合同核验。旧版 CSV 导入、回测和历史模拟入口保留在 `/legacy`。

原 API 和数据格式见 `G1_G5_API.md`；原功能及边界说明见 `G1_G5_DELIVERY.md`。长期成长路线原稿保留在 `docs/long-term-roadmap-20260922` 分支的 `docs/LONG_TERM_ROADMAP.md`，本文件是实现对账，不替换原经验门槛。
