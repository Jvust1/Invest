# Invest v0.1 数据格式与执行前提

核对日期：2026-09-22。本文对应 `invest/data.py` 与 `invest/engine.py` 的 v0.1 实现。支持人民币、沪深主板普通股票、日线、现金账户；不支持 ETF、科创板、创业板、北交所、港美股、融资融券或真实券商下单。

导入成功表示数据可以接受结构检查和研究展示。它不自动表示数据真实、完整或能够用于模拟成交。执行引擎还会独立检查所选股票、评价区间和均线预热区间。

## 1. 导入时先声明来源和单位

市场 CSV 与独立开市日历 CSV 配套使用。界面/API 的导入请求需要：

| 参数 | 含义 |
| --- | --- |
| `csv` | 市场 CSV 文本 |
| `source` | 1–500 字符的来源说明；不能空白或含控制字符。建议写明供应方、导出日期、产品/接口及覆盖区间 |
| `calendar_csv` | 独立开市日历文本；可留空用于研究检查，但不能执行回测或模拟成交 |
| `raw_prices_confirmed` | 必须明确为 `true`，确认所有价格为人民币未复权价格 |
| `volume_shares_confirmed` | 必须明确为 `true`，确认成交量已经换算为整数股数 |

两项确认是供应方声明，程序不能仅靠 CSV 判断价格是否经过复权、股票是否真实存在或日历是否完整。前复权/后复权收盘价不能混入原始 OHLC；也不能只把“手”列改名为 `volume_shares`。程序不自动识别或补做复权。

Python 函数 `parse_csv(text, source=..., calendar_csv=...)` 本身以调用者已经声明单位为前提；HTTP 层另行要求上述两个确认字段。市场文件及日历分别最多 2 MiB，市场文件最多 10,000 行行情，日历最多 10,000 行日期；HTTP 请求整体还受服务端请求体大小限制。

## 2. 市场 CSV 字段

使用 UTF-8 文本、英文逗号和一行表头；允许 UTF-8 BOM。列顺序可以改变，字段名大小写必须符合下表。程序去除表头和字段首尾空白，但不接受重复表头、未知列、少列/多列的记录、破损引号或夹入的空白行。不要附加索引列、公司名称列或 Excel 合计行。

| 字段 | CSV 是否必填 | 取值和含义 | 对执行的要求 |
| --- | --- | --- | --- |
| `symbol` | 必填 | 标准代码字符串，如 `600000.SH`、`000001.SZ`；保留前导零 | 必须属于当前支持的代码格式 |
| `date` | 必填 | `YYYY-MM-DD`；有效历史日期，不含时分秒或时区；不能晚于中国时区当日 | 必须出现在独立开市日历中 |
| `open` | 必填 | 未复权开盘价，人民币元/股 | 正数且精确到分 |
| `high` | 必填 | 未复权最高价，人民币元/股 | 不低于 `open`、`close`、`low` |
| `low` | 必填 | 未复权最低价，人民币元/股 | 不高于 `open`、`close`、`high` |
| `close` | 必填 | 未复权收盘价，人民币元/股 | 正数且处于 `[low, high]` 内 |
| `volume_shares` | 必填 | 非负整数股数，可为 `0` | 零成交量不允许模拟成交 |
| `suspended` | 可缺列或留空 | `true` / `false`；忽略英文大小写。空值保留未知 | 必须已知；为 `true` 的记录成交量必须为 `0`，当日不成交 |
| `up_limit` | 可缺列或留空 | 当日、该证券的真实涨停价，人民币元/股 | 执行必须有明确正数价格，不能凭代码推算 |
| `down_limit` | 可缺列或留空 | 当日、该证券的真实跌停价，人民币元/股 | 必须低于 `up_limit`，且不高于当日最低价 |
| `adj_factor` | 可缺列或留空 | 已核对的正复权因子；此列用于检查，不把价格乘以该因子 | 所选执行及预热区间内必须已知且不变 |
| `corporate_action` | 可缺列或留空 | `true` / `false`；声明当日是否发生当前引擎不支持的公司行动 | 必须明确为 `false`；`true` 和未知均阻断执行 |

`suspended` 与 `corporate_action` 不接受 `0/1`、`yes/no` 或“是/否”。CSV 中的 `null`、`None`、`NaN` 不是空值；缺失可选值应使用空字段。标准化后，缺失值成为 JSON `null`，不会被改成 `false`、`0` 或 `1`。

数值必须有限，不能含千位分隔符、货币符号或百分号。价格按 0.01 元刻度检查，不能给出分以下价格；成交股数必须为整数。CSV 解析设有数值上限，执行检查更严格：价格不超过 1,000,000 元/股、成交量不超过 1,000,000,000,000 股。通过导入仍可能因为超出执行范围而不能回测。

### 支持的代码格式

| 市场 | 当前接受的六位代码前缀 | 后缀 |
| --- | --- | --- |
| 上海主板 | `600`、`601`、`603`、`605` | `.SH` |
| 深圳主板 | `000`、`001`、`002`、`003` | `.SZ` |

其余后三位必须为数字。代码格式校验不是证券主数据核验：它不证明证券存在、某日已经上市、没有退市、属于普通交易状态或适合特定账户交易。风险警示、上市初期等情形不能套用统一百分比；真实涨跌停价必须按证券与日期提供。无涨跌幅限制的特殊交易日暂未建模，不能用任意很大的上下限伪装。

### 顺序和唯一性

同一 `symbol` 的输入行必须按日期严格递增，不能有重复的“代码 + 日期”。不同代码可以分组，也可以交错；导入后统一按 `date, symbol` 排序。程序拒绝同一代码的倒序输入，不会静默修复供应方的重复记录。

## 3. 独立交易日历

日历只含开市日，一行一个日期，可有 `date` 表头：

```csv
date
2024-01-02
2024-01-03
2024-01-04
```

也可以省略表头。日期必须严格递增、真实存在且不重复，不接受额外列。必须从独立可靠来源取得开市日集合，不能用行情已有日期反推日历，也不能把周一至周五直接当作真实开市日；否则无法发现整天行情缺失。

检查行为如下：

1. 行情出现在声明日历以外：记为 `date_outside_calendar` 错误。
2. 某只股票第一行至最后一行之间，日历存在而行情缺少的日期：记为 `missing_session` 错误。程序不插值、不前向填充，也不猜测停牌。
3. 已确认停牌的开市日：供应方仍应显式提供一行，标为 `suspended=true`、成交量为 `0`，并提供有依据、满足格式和上下限约束的 OHLC。若无法可靠补齐，则保留缺口并接受执行被阻断。
4. 缺失日历：研究数据可保留，执行被阻断。

同一数据集的股票共用一份日历。执行引擎会要求所选股票在选中窗口内的行情日期与日历逐项一致，并验证均线预热所需的历史记录。日历完整性本身仍是来源责任，哈希和格式检查不能证明供应方没有遗漏开市日。

## 4. 最小完整格式示例

以下数字完全虚构，仅演示格式，不代表代码对应证券的实际行情，也不是一份足够进行默认 20 日均线回测的数据：

```csv
symbol,date,open,high,low,close,volume_shares,suspended,up_limit,down_limit,adj_factor,corporate_action
600000.SH,2024-01-02,10.00,10.20,9.90,10.10,1000000,false,11.00,9.00,1,false
600000.SH,2024-01-03,10.10,10.30,10.00,10.20,1100000,false,11.11,9.09,1,false
600000.SH,2024-01-04,10.20,10.40,10.10,10.30,1200000,false,11.22,9.18,1,false
```

使用上一节的三行日历；来源写明“文档合成格式示例”。这里只说明声明字段能通过结构检查，不证明字段具备真实交易所依据。

只提供七个必填字段也可导入研究，但五个可选字段将显示为未知。要使用真实历史区间进行模拟，需补齐真实可追溯的执行信息；不能为了消除红色提示而批量填入 `false`、因子 `1` 或固定涨跌停价。

## 5. 审计结果与公司行动

标准化数据集包含：

| 顶层字段 | 内容 |
| --- | --- |
| `id` | 64 位十六进制 SHA-256 内容指纹 |
| `meta` | `source`、`source_kind`、`currency=CNY`、`price_basis=raw`、`volume_unit=shares`、`retrieved_at`、`calendar_source`、`schema_version=1` 等 |
| `bars` | 排序后的市场记录，缺失可选字段保留 `null` |
| `calendar` | 严格递增的开市日期列表 |
| `audit.errors` | 日历缺口、上下限矛盾、停牌与成交量冲突等数据问题 |
| `audit.warnings` | 来源声明边界、零成交量、供应商补充信息缺失等提示 |
| `audit.backtest_blockers` | 错误与缺失执行事实等阻断项 |
| `audit.backtest_ready` | 对完整数据集的审计摘要；不是独立市场认证 |

结构/数值错误会直接拒绝整个导入；可审查的金融信息缺失或日历问题则保留在审计结果中。每条审计项有 `code`、`message`，适用时带 `symbol`、`date`，方便回到具体数据核对。引擎不信任手工改成 `true` 的 `backtest_ready`，会重新验证内容指纹及实际执行窗口。某个其他股票或窗口之外的阻断也不替代当前窗口的独立验证。

v0.1 不处理现金分红、送股、转增、配股及其税费/到账时点，也不把复权价格当成真实成交价格。公司行动为 `true`、状态未知、复权因子缺失或窗口内发生变化，都会阻断执行。因子不变只是必要条件之一，不能单独证明没有公司行动；必须同时有可信的 `corporate_action=false` 声明。研究面板使用原始价格做算术摘要，跨公司行动的涨跌不等于含分红的经济总回报。

指纹基于标准化后的全部 `bars`、`calendar` 和除 `retrieved_at` 外的 `meta`，不直接对原 CSV 排版计算。相同内容、来源及日历产生相同身份；仅重新取得数据的时间变化不产生新身份。来源、单位或内容变化会产生新身份。审计摘要不是指纹的权威输入，执行规则也不能只依赖旧摘要。

## 6. AKShare 真实历史行情研究通道

安装 `py -m pip install -e ".[market]"` 后，可通过网页或 `fetch_akshare(symbol, start, end)` 获取真实 A 股不复权日线。当前锁定兼容版本 `akshare==1.18.97`。

使用接口：

- `stock_zh_a_hist(..., period="daily", adjust="")`：真实日频 OHLCV；
- `tool_trade_date_hist_sina()`：独立交易日历。

标准化规则：

- 代码仍使用 `600000.SH` / `000001.SZ`；
- AKShare 历史日线的“成交量”按其文档口径视为“手”，精确乘以 100 转为 `volume_shares`；
- 只接受不复权价格，不把 qfq/hfq 数据当作真实成交价；
- 请求日期最多 366 个自然日；
- 供应商返回证券、日期、字段或成交量转换异常时直接失败，不生成替代数据。

边界：AKShare 日线与交易日历可以提供真实价格研究，但并不能单独证明停牌、公司行动、历史风险警示、存活偏差、PIT 特征或每个交易日的完整执行语义。`suspended`、`corporate_action`、`up_limit`、`down_limit`、`adj_factor` 因此保持未知，审计结果默认阻止回测/模拟成交。这样可以使用真实行情做观察和研究，同时不把缺失信息静默伪造成 `false` 或固定规则。

AKShare 项目采用 MIT License，并声明数据用于学术/研究参考；上游数据源条款仍需遵守，接口也可能随上游变化。Invest 不绕过访问限制、不做高频抓取、不提供 IP 轮换或其它规避机制。

## 7. Tushare v0.1 仅供研究导入

当前适配器只调用四个官方接口：

| 官方接口 | v0.1 使用方式 |
| --- | --- |
| [`daily`](https://tushare.pro/document/2?doc_id=27) | 获取未复权 OHLC；把 `vol` 从“手”乘以 100，用十进制精确换算为整数股数。停牌期间该接口不提供行情 |
| [`trade_cal`](https://tushare.pro/document/2?doc_id=26) | 按代码后缀选择 `SSE` / `SZSE`；检查请求区间自然日覆盖，再只保留开市日 |
| [`stk_limit`](https://tushare.pro/document/2?doc_id=183) | 按证券及日期取得明确的上下限价格，不自行套用 10% 或 5% |
| [`adj_factor`](https://tushare.pro/document/2?doc_id=28) | 取得因子供审计与变化检查；不据此生成复权成交价 |

这四项不构成完整停复牌或公司行动证明。当前 `suspended`、`corporate_action` 都保留未知，因此 **Tushare 导入结果不能直接用于回测或模拟成交**。这项限制不会因价格、因子和上下限齐全而自动解除。后续需增加经验证的停复牌/公司行动资料与处理规则，不能只把未知值改成 `false`。相关待研究接口见 [参考与规则](REFERENCES_AND_RULES.md)。

每次只获取一只受支持股票，最多 366 个自然日。`daily` 失败或为空直接报错；辅助接口权限不足、返回不完整或日历缺失时，程序保留可研究的日线及明确阻断，不生成替代行情。交易日缺少日线也不会被自动解释为停牌或未上市。

正常使用由服务端环境变量 `TUSHARE_TOKEN` 提供凭据。浏览器不提交 token，数据集和导出文件不包含 token。请求仅发往 `https://api.tushare.pro`，拒绝重定向；不抓取非官方行情网页、不自动购买权限。当前验证使用合成数据及 mock；真实 token、账户权限、在线返回和真实行情均尚未验收。

## 8. 仓库演示数据

`examples/SYNTHETIC_DEMO_prices.csv` 是 **140 个合成开市日 × 2 个示例代码，共 280 条虚构行情**；配套 `SYNTHETIC_DEMO_calendar.csv` 是未扣除中国节假日的工作日日历。价格、成交量、上下限及公司行动字段都是演示构造，不能充当真实行情或正式研究结论。

建议通过“加载演示数据”使用 `demo_dataset()`，以保留 `source_kind=demo` 和各页面的合成标签。直接导入示例 CSV 时，它走普通 CSV 路径，来源必须明确写“合成演示：虚构价格和日历”，不能冒称真实数据。详见 [examples/README.md](../examples/README.md)。

## 9. 复用与执行边界

默认回测还需要至少长均线周期的预热记录和一个可评价交易日；字段完整不代表样本长度足够。固定佣金、印花税、过户费及滑点必须由使用者确认，具体情景和不适用范围见 [参考与规则](REFERENCES_AND_RULES.md)。

模拟账户保存的是人工记录的历史纸面交易，数据来源与指纹用于追踪本次结果和持仓。不要把不同数据源的历史、不同复权体系或被修改的同名文件当作可无缝互换的版本。v0.1 没有券商通道，也没有真实成交或收益验证。
