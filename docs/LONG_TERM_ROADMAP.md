# Invest 长期发展路线图

制定日期：2026-09-22。视野：未来 12 个月。
性质：人民币投资研究工具的发展计划；所有新能力与量化指标均为提案。
节奏：全项目同时一个主项目和一个支撑项目；Invest 获得主项目窗口时，NCMCM 只承担必要的通用研究底座支持。
时间窗口从项目启用开始计算，不代表十二个项目同时满负荷施工。

## 1. 定位

建立一个人民币计价、面向 A 股研究与模拟复盘的个人工作台，让每项研究有来源、每次回测可复现、每个风险判断有可解释证据。
优先帮助用户看懂自己的数据、策略和持仓风险，而不是制造确定上涨的预测。
人民币是默认记账货币；不以美元账户、海外付费服务或外币资产作为启动前提。
ETF 等产品可纳入研究范围，但具体市场、账户权限、资金规模和风险承受能力尚未确认，不能据此假设用户能买任何标的。

推荐路线：数据可信 → 简单基准 → 成本真实的历史验证 → 模拟跟踪 → 人工复盘。
本年度默认保持研究与模拟用途；任何实盘账户或订单接入都另做需求、权限与资金边界审查，不由本路线图自动触发。
盈利、胜率和年化收益不作为软件交付承诺。

## 3. 架构建议与不做的事

建议先采用一个简单可测试的 Python 研究核心，输入文件、规范化数据、研究配置、回测结果和报告分层。
UI 在核心可验证后再加入，不同时建设多端重平台。

| 层 | 责任 | 关键边界 |
|---|---|---|
| 数据适配 | 读取经授权 CSV/API 与数据字典 | 数据源故障不可静默换源 |
| 标准数据 | 时间、证券身份、价格、成交量、可见日期 | 保留原始价格与复权口径，不覆盖来源 |
| 质量审计 | 缺失、重复、异常、停牌、退市、时间泄漏 | 不用未来数据填充过去未知值 |
| 研究配置 | 策略、参数、样本期、费用、约束 | 参数与结论版本绑定 |
| 验证引擎 | 基准、成本、交易可行性、逐笔账本 | 信号时间与可成交时间分开 |
| 风险报告 | 回撤、集中度、敞口、流动性与不确定性 | 统计描述不冒充买卖指令 |
| 实验台账 | 输入/代码/规则版本与结果哈希 | 失败结果也保留 |

不在首期做高频交易、杠杆策略、多市场货币换算、自动下单、全网新闻爬取或昂贵的大模型预测系统。
这些排除项是为了给可信研究留出资源，未来有真实需求和证据时再逐项评估。

## 4. 第一阶段：0–30 天，可信数据与可运行雏形

### 交付

1. 项目 North Star、数据来源表、证券身份规则和人民币预算表。
2. 可独立运行的离线输入检查器与规范化输出，不先依赖收费 API。
3. 一个小规模、明确授权、身份冻结的研究数据样本；样本不代表全市场。
4. 现金基准与简单买入持有基准，用于检查净值和成本算术。
5. 一份可人工复核的逐笔交易/现金/持仓账本及中文报告。

### 建议验收目标

- 至少覆盖重复时间、乱序、缺列、非法价格、空文件、缺失日、证券更名/代码冲突等 20 类边界。
- 每份输入都记录来源、获取时间、许可/用途限制、价格口径、时区、字节数和哈希。
- 同输入、同代码、同配置重复运行，业务结果完全一致；运行时间戳放独立元数据。
- 10 个手工可计算交易场景中，现金、持仓、费用和净值在声明的数值精度内吻合。
- 不把无法验证的数据质量字段默认为通过；错误能定位到行和字段。

### 前置条件

安全初始化分支已完成登记和回读，普通工作使用继承保护的非默认分支。
数据许可未明确时只使用人工构造/允许使用的样本，不先抓取大规模数据再考虑合规与成本。

## 5. 第二阶段：31–90 天，真实约束下的历史验证

### 交付

- 统一研究协议：假设、可用信息时点、训练/验证/留出时间段、参数搜索预算、评价指标。
- 先比较不超过 3 类简单、可解释的研究假设；例如趋势、估值或资产配置思想，均不直接作为用户买卖建议。
- 交易规则按市场、板块、产品、日期版本化，覆盖交易日、停牌、涨跌幅限制、最小申报单位、回转限制、费用与分红等因素。
- 财务或公告特征使用实际公开可见时间，不只用报告期末时间。
- 加入幸存者偏差、成分变化、退市样本与复权一致性审查。
- 引擎做成本/滑点/流动性敏感性分析，与简易独立账本对照。

具体交易参数在实施时以交易所现行规则及实际产品/券商条件逐项核实，不在路线图硬编码一套永远有效的数字。
[深交所规则目录](https://www.szse.cn/lawrules/rule/trade/)提供股票、基金和通用规则的不同入口，产品类别应分别核验。

### 建议验收目标

- 每个研究实验 100% 记录训练/验证/留出边界；禁止随机切分后声称真实时间外推有效。
- 特征生成与拟合只接触当时可见数据，至少 15 个对抗样例验证未来信息不进入过去决策。
- 至少 3 组成本情景、3 个不同历史阶段、1 个简单基准完整报告，不挑选好看的区间。
- 使用第二份独立账本复核关键交易；发现无法成交的理想成交假设时结果降级为不可用。
- 留出集首次观察结果冻结；重新调参后使用新的验证协议，不把旧样本重新称作未见数据。

### 退出条件

数据质量与交易约束未通过时，暂停比较收益高低，先修正研究流程。
时间切分可研究 TimeSeriesSplit，但它不能自动解决公告可见时点、重叠标签和所有形式的信息泄漏。[官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

## 6. 第三阶段：第 4–6 月，模拟持仓与风险复盘

### 交付

1. 模拟组合、观察清单和研究日志，明确标记模拟、历史回测与人工实际记录。
2. 支持人工导入脱敏持仓记录；不存券商密码、Token 或完整账户号。
3. 每次模拟决策记录当时证据、理由、预期风险、撤销条件与后续结果。
4. 风险报告覆盖集中度、相关性、历史回撤、成交可行性和数据过期状态。
5. 每周/每月复盘模板，分清市场变化、策略变化、执行偏差与数据问题。

### 建议验收目标

- 连续 8–12 周模拟跟踪；缺数据与任务失败可见，不用补写的历史信号冒充实时信号。
- 每个模拟动作都有当时可用证据与版本，回溯可解释率 100%。
- 人工导入对账至少 3 组带分红、费用、资金流入流出的样例。
- 系统报告区分收益变化与外部资金变化；不能用资产总额增加直接声称投资收益。
- 核心报告在无模型 API 时仍能生成；模型只辅助解释，数字来自确定性计算。

这一阶段不设必须跑赢市场的门槛；可靠性与诚实记录优先，差的策略也应能得到可信的否定结果。

## 7. 第四阶段：第 7–12 月，个人研究工作台稳定化

### 交付候选

- 中文交互界面：数据状态、假设比较、风险、模拟日志、报告导出五个清晰入口。
- 指标和图表可回链到研究版本与输入数据；允许解释“为什么这次不能得出结论”。
- 可选定时数据更新与告警，先做失败通知和过期标记，再加复杂推荐。
- 完成一次从备份恢复代码、配置、脱敏记录和报告的演练。
- 评估是否存在稳定价值后，决定继续纯研究、支持人工决策，或另立实盘接入设计。

### 建议验收目标

- 两个连续月度版本可由他人/新会话按文档复现关键报告。
- 常见任务 5 分钟内找到数据质量、假设、结果和失败原因；先测基线再优化。
- 运行失败、源变更与过期状态 100% 可见；零静默合成当期行情。
- 月度人民币成本在用户确认预算内；预算未定前只开无需新增付费的能力。
- 完成一次复杂度审查；若发现无增益模块，提出停用或简化方案并记录依据，避免为达成指标人为新增或删除模块。

## 9. 首个两周

- 第 1–2 天：读取本轮之后新增分支；复用已经完成的模块，核对 IN-01，不重复初始化。
- 第 3–4 天：定义标准数据合同与最小离线样本，先做价格、币种、时间身份。
- 第 5–7 天：完成审计与确定性账本，以人工可算样例找错。
- 第 8–10 天：生成首份中文研究报告，只展示基准和数据质量，不急于加入预测模型。
- 第 11–14 天：独立复核、记录环境与成本、恢复演练，然后才排下一组假设。
- 唯一首步：IN-01；若并发工作已有数据骨架，则先对账其证据并进入首个尚未完成项。

## 11. 资源、风险与暂停机制

优先 CPU 与已有设备；先测性能再增加 GPU/云资源。模型与大缓存依全局规则放 D 盘。
预算表至少分数据费、模型费、运行费、存储费，均以人民币记录；免费服务也记录许可、限流和稳定性。

| 风险 | 检测信号 | 行动 |
|---|---|---|
| 数据失真或许可不明 | 字段突变、来源不可追溯 | 暂停相关研究，保留上版数据 |
| 未来信息泄漏 | 时间对抗样例失败 | 撤销有效性结论，修复后新协议重跑 |
| 回测过拟合 | 调参次数多、留出失效 | 限制搜索预算，保留失败，换未见验证 |
| 不真实成交 | 停牌/涨跌限制下仍理想成交 | 暂停收益比较并修复交易模型 |
| 成本超预算 | 月度账单高于批准上限 | 停止新增付费任务，退回离线 |
| 复杂度无收益 | 两周期无法解释新模块价值 | 停止扩张，简化架构 |

没有证据的策略标为未验证，不用大模型流畅解释提升可信等级。
资金风险承受度未知时，不给默认仓位或亏损额度；这些设置在未来具体任务中确认。

## 12. 月度复盘与后续年度

每月只回答：数据更可信吗、结果更可复现吗、解释更清楚吗、成本更可控吗。
以最新真实证据更新路线图，阶段完成记录 commit、输入身份、协议、结果、审查者和未解决限制。
连续三个月有稳定使用价值后，第二年才考虑更广数据、多人协作或额外市场；否则优先做轻量个人工具。
年度交付可以是一个可靠的否定假设与风险复盘工具，不以“自动赚钱”判断成败。
