## 1. 项目要成长为什么

Invest 面向人民币计价的 A 股研究与模拟复盘，逐步成为可追溯、可重复运行的个人投研工作台。
最小价值是用户能看清一份数据是否可信、一个计算是否正确、一个研究假设是否经得住检验。
更大的价值是把多个研究、模拟组合和风险解释组织起来，帮助用户形成可持续复盘的个人研究方法。
人民币是默认记账货币；启动不依赖美元账户、海外付费服务或外币资产。
ETF 等产品可以作为后续研究对象，但须先确认对应市场、数据、交易规则和用户需求。
具体账户权限、资金规模和风险承受能力尚未确认，不假设用户能买任何标的。

本路线图覆盖研究与模拟。实盘账户和订单接入属于独立需求与权限设计，不能由成长级别自动解锁。
盈利、胜率和年化收益不是软件交付承诺；能可靠否定一个无效假设，也属于有效成果。
扩大研究对象、增加模型或增加自动化，均须证明能解决当前规模遇到的问题。

## 3. 成长总览

| 成长级 | 用户新增价值 | 功能与规模如何扩大 | 升级所需证据 |
|---|---|---|---|
| G1 可信研究样本 | 看懂数据质量与基本收益计算 | 一个来源明确的数据样本、一套人民币账本、一份基准报告 | 数据身份完整、异常可定位、手算与重复运行一致 |
| G2 可验证的假设实验室 | 公平比较不同研究假设 | 从单一基准扩展到有限假设、不同历史样本与成本情景 | 交易约束、时间外验证、失败结果和成本敏感性均可审查 |
| G3 可持续模拟组合 | 跟踪假设在后续可见信息中的表现 | 从离线实验扩展到模拟组合、观察清单与风险事件 | 决策时间证据完整、账本一致、异常与缺数据可见 |
| G4 个人投研工作台 | 独立完成数据检查、比较、解释与复盘 | 多个研究和组合共享稳定流程、中文界面与恢复机制 | 新会话可复现、版本可恢复、维护成本可承担 |
| G5 需求驱动的研究扩展 | 解决当前工具无法覆盖的新问题 | 按需增加数据来源、人民币产品类型或可复用适配器 | 新需求独立成立，许可、规则、隔离评测和资源评估通过 |

成长级表示能力与使用范围的提升，不对应月份或期限。
各级可以局部重叠，但依赖未通过的输出不得成为下游的可信输入。
数据规模、策略数量、模型复杂度和自动化程度分别评估，不要求一起扩大。
时间戳、市场样本区间和模拟观测长度用于判断证据质量，不能单独触发升级。

## 4. G1：从零散数据到可信研究样本

### 进入条件

- 已恢复当前治理和实际代码状态，选定继承完整安全策略的非默认分支。
- 明确一个最小研究问题及允许使用的数据样本；许可不明时使用人工构造样本。
- 记录证券身份、人民币计价、时区、价格与复权口径、输入来源和资源预算。

### 能力与规模增量

1. 建立离线输入检查器，覆盖 CSV 等当前确实需要的格式。
2. 固定原始输入、规范化数据、质量报告、研究配置和计算结果之间的身份关系。
3. 提供现金基准与简单买入持有基准，核验收益、现金、持仓和费用算术。
4. 输出可逐笔人工复核的账本和中文报告，明确样本覆盖范围。
5. 先形成一个端到端例子，再增加第二份不同边界的数据；不以全市场覆盖作为起步条件。

### 验收与升级门槛

- 至少覆盖重复时间、乱序、缺列、非法价格、空文件、缺失日、更名和代码冲突等 20 类边界。
- 每份输入均有来源、获取时间、许可、价格口径、时区、大小和哈希；未知质量项保持可见。
- 同输入、同代码和同配置重复运行，业务结果完全一致；运行时间戳与业务结果分开。
- 10 个手工可计算场景中，现金、持仓、费用与净值在声明精度内一致。
- 用户或审阅者能从报告定位到原始记录和具体计算；验证失败不得输出默认通过。

### 维持或收缩条件

若数据身份和账本仍不稳定，继续只处理小样本；来源问题解决前暂停增加模型、UI 和数据源。
只需要核查少量历史记录时，G1 可以直接成为实用小工具，无须升级。

## 5. G2：从一个基准到可验证的假设实验室

### 进入条件

G1 的数据与账本验证通过，且已经出现必须比较不同假设或解释失效原因的实际研究问题。
先选不超过 3 类简单、可解释的候选思想，给每个假设定义适用范围和否定条件。

### 能力与规模增量

- 统一研究协议：假设、当时可见信息、训练/验证/留出区间、参数搜索预算和评价指标。
- 扩大的是可审查的研究差异：不同历史环境、成本情景与基准，不以参数组合数量作为成果。
- 交易规则按市场、板块、产品、有效日期版本化，记录停牌、成交限制、费用、分红等约束。
- 财务与公告特征使用实际公开可见时间；保留证券池变化、退市样本和复权一致性审查。
- 分开信号生成时间与可成交时间，用第二份独立账本核验回测引擎。
- 保存被否定的假设、失败实验与调参预算，防止只展示优胜结果。

### 验收与升级门槛

- 每个实验完整记录时间边界；拟合和特征仅接触当时可见的数据。
- 至少 15 个对抗样例验证未来信息不能进入过去决策。
- 至少 3 组成本情景、3 个历史环境及 1 个简单基准采用同一协议比较。
- 不可成交的理想订单被识别并报告；关键交易与独立账本一致。
- 留出集首次观察结果保持冻结；调参后采用新验证协议，不重复声称同一数据未见。
- 输出能解释假设成立范围与失效原因；计算准确、证据透明优先于收益排名。

### 维持或收缩条件

发现信息泄漏、数据选择偏差或不真实成交时，退回相关基础能力修复，再重建验证证据。
比较更多模型不能改善研究判断时，保持简单候选集，不增加复杂预测系统。
具体交易参数在实施时查验现行官方规则与实际产品条件；不在路线图中固定永远有效的数字。

## 6. G3：从离线实验到可持续模拟组合

### 进入条件

G2 已产出可复现研究协议，用户确有跟踪后续表现的需求，且数据更新与缺失状态可以明确判断。
建立模拟身份和决策日志，清楚区分历史回测、模拟跟踪和人工实际记录。

### 能力与规模增量

1. 增加模拟组合、观察清单和当时可用证据的决策记录。
2. 从单一策略曲线扩大到组合层面的集中度、相关性、回撤、成交可行性和数据过期检查。
3. 按需支持用户授权的脱敏持仓导入；不存券商密码、Token 或完整账户号。
4. 对每次动作记录理由、风险、撤销条件和后续结果，区分市场变化、策略变化与执行偏差。
5. 让异常更新、缺失行情和重复任务成为可见状态；核心数字由确定性计算产生。

### 验收与升级门槛

- 模拟证据覆盖更新、缺失、失败、重试和资金流变化；每个动作均可还原到当时信息版本。
- 建议积累连续 8–12 周的模拟观察，以暴露运行问题；这只是证据观察窗口，经过该时长不会自动升级，也不能证明策略有效。
- 至少 3 组带分红、费用和资金流入流出的样例通过人工对账。
- 收益变化与外部资金变化分开计算，缺数据时不补造实时信号。
- 报告可在没有模型 API 的情况下生成；模型解释不能修改确定性数字。
- 后续证据能推翻原假设，并保留否定结论与原始记录。

### 维持或收缩条件

若模拟日志、组合账本或数据更新不可靠，停止新增组合并修复现有链路。
本级没有跑赢市场的交付门槛，也不因模拟表现良好自动获得实盘接入权限。

## 7. G4：从研究脚本到个人投研工作台

### 进入条件

已有多个真实研究或模拟任务，用户在定位报告、比较版本、查找失败或恢复环境上出现重复负担。
核心计算与输入合同稳定，界面设计有实际任务依据。

### 能力与规模增量

- 增加中文界面，组织数据状态、假设比较、风险、模拟日志与报告导出五类任务。
- 多个研究与组合使用同一套版本化流程，允许用户追溯任一图表的数据与配置。
- 增加备份恢复、输入更新、失败提示、数据过期标记和受控的重复任务处理。
- 把说明、代码、配置与报告连成可恢复入口，使新会话或另一设备能接续工作。
- 依据实际瓶颈改善性能和维护方式；避免提前同时建设多端客户端。

### 验收与升级门槛

- 两个连续候选版本均可由新会话按文档复现关键报告；候选版本按能力变更产生。
- 常见任务可在 5 分钟内定位数据质量、假设、结果和失败原因；该时长是可用性测量。
- 一次完整备份恢复演练重建代码、配置、脱敏记录与报告，身份和业务结果一致。
- 运行失败、来源变更和过期状态完整可见，不能静默合成当期行情。
- 人民币成本处于已确认预算内；预算未定时只启用无需新增付费的能力。
- 复杂度评审证明新增组件带来实际收益；无增益模块提出简化方案，不为指标人为增删模块。

### 维持或收缩条件

单人研究需求已经充分满足时，长期保持这一规模；无需为了扩大项目增加用户、市场或云服务。
维护负担超过使用收益时，保留数据和结果身份，回到较轻的本地工具流程。

## 8. G5：从稳定工作台到需求驱动的研究扩展

### 进入条件

G4 已有稳定使用证据，新的研究问题明确超出当前范围，而且现有模块不能以简单配置解决。
每个扩展分别形成需求、数据、规则、成本、权限和评测记录，不把所有方向打包启动。

### 可选择的扩展轴

| 扩展轴 | 新增能力与价值 | 独立条件与范围限制 |
|---|---|---|
| 数据深度 | 从价格数据扩展到可追溯财务或公告特征 | 许可、可见时间与修订历史可验证；新增信息泄漏审查 |
| 人民币产品范围 | 研究需求成立时增加相应 ETF 等产品 | 产品规则和数据口径单独核验；不继承股票成交假设 |
| 研究任务规模 | 多个假设、组合共享任务队列和实验索引 | 隔离配置、并发资源和失败恢复经过验证 |
| 能力复用 | 将重复使用的审计/实验接口稳定供其他项目调用 | 至少两个真实消费场景、版本契约和兼容证据 |
| 人工决策支持 | 改善用户阅读研究与复盘风险的过程 | 解释依据透明；不变成自动交易权限 |

每条扩展先以小范围适配验证，再决定是否推广；原有工作台必须可以独立运行。
更广市场、多币种、多人服务、杠杆、高频和实盘接入均不属于本计划默认解锁的能力。
若未来明确提出其中某项，另做产品范围、权限、资源和风险方案。

### 验收与止步条件

- 新扩展有独立用户价值和对照证据，不能只增加数据量、模型数或文档数。
- 在新的隔离样本上验证规则、数据与结果；不改写原有冻结结论。
- 关闭扩展后，原工作台的研究、报告和记录仍可用。
- 使用收益不能覆盖维护与数据成本时，停止推广并保留可恢复成果。

## 9. 能力架构与跨库边界

采用可测试的 Python 研究核心，依次明确数据适配、标准数据、质量审计、研究配置、验证引擎、风险报告和实验台账的责任。
数据源故障不可静默换源；原始价格与复权口径分别保留；输入、代码、规则和输出身份互相关联。
规模扩大优先增加版本化适配器，出现实际维护或性能瓶颈后再调整部署结构。

| 仓库 | 可复用或交换 | 始终保持的边界 |
|---|---|---|
| NCMCM | 数据质量、实验协议、模型比较与配置身份 | 竞赛线、冻结结果与 provider/solver 执行授权独立 |
| Book | 经来源核验的金融学习材料链接 | 教材观点不充当实时交易数据或具体买卖结论 |
| mygpt | 用户允许的研究任务提醒与公开状态摘要 | 账户、持仓明细和券商凭据默认不共享 |
| AutoFlow | 可选非交易研究任务的重复操作 | 不操作券商买卖页面，不绕过确认 |
| ChatContextVault | 默认无依赖 | 私人聊天不进入金融画像或模型训练 |

先使用小型版本化输入/输出接口；真实重复需求和测试成熟后才考虑公共包。
新能力不得继承别的项目的访问、运行、合并或资金授权。

## 11. 资源、暂停和回退

优先 CPU 与已有设备；测出实际瓶颈后再考虑 GPU 或云资源。模型与大缓存遵守全局 D 盘存储规则。
成本用人民币记录，区分数据费、模型费、运行费和存储费；免费服务仍记录许可、限流与稳定性。

| 风险信号 | 暂停或收缩动作 |
|---|---|
| 来源不可追溯、许可不明或字段含义突变 | 暂停相关数据研究，保留已核验版本 |
| 未来信息泄漏或留出集污染 | 撤回相关有效性判断，使用新协议复验 |
| 停牌或限制场景中出现理想成交 | 停止收益比较，修复交易模型 |
| 模拟日志缺证据或资金流无法对账 | 停止增加组合，修复现有记录链 |
| 付费成本超出已确认预算 | 停止新增付费任务，退回可用离线能力 |
| 连续两次能力评审均无法说明新增模块价值 | 停止扩张，提出简化方案并保留历史成果 |

未知风险承受能力时不设置默认仓位或可承受亏损额度；未来具体任务再确认这些条件。
没有证据的假设继续标记未验证，语言模型解释不提高其可信等级。

## 12. 按成长证据触发复盘

以下事件触发路线复核：一个成长级通过验收、新需求出现、数据或规则改变、规模瓶颈出现、失败证据推翻原假设、成本越界。
每次复盘回答：用户新增获得了什么、证据在哪里、当前规模遇到什么障碍、扩大哪一条轴才有价值。
记录候选能力、已验证能力、待修复能力和明确不做的方向；不能用提交数或项目年龄评定成熟度。
升级记录包括输入身份、代码、协议、结果、审阅证据、未解决限制和可恢复路径。
可以选择扩展、维持、收缩或暂停；这些都是基于需求和证据的正常结果。
