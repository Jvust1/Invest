# ENG-03：版本化成交合同 v0.2

## 本轮目标与交付范围

本模块接续 `c288dcb886df6ab415db76015cddc597aad1c748` 的独立执行实验室。在原工作台和 v1 比较器之外新增可运行的成交规则参考实现、内容寻址的规则清单、原生兼容性检查、共享成交容量账本、报告及回归测试。不是新 EXE，也没有把新规则默认为生产回测规则。

本轮所有输入均为人工合成数据。日期只是声明的测试会话；完整日成交量属于回顾性测试上限，不是开盘时已知的流动性。三种规则都不构成官方市场规则或策略/收益建议。未接真实行情、券商、账户、模型服务，未开启留出集，也未开始真实前向观察。

## 1. 三个明确且不可随意改写的规则版本

| 规则版本 | 同日成交容量 | 不足时 | 价格和费用 | RQAlpha 原生支持 |
|---|---|---|---|---|
| `strict-partial-v1`（默认） | 买卖共用证券/会话容量 | 部分成交，余量立即取消 | 价格按不利方向到分，超 OHLC 拒绝；分项费用到分，保留显式过户费用 | 不支持；只运行新的参考执行器，明确列出差异，不偷偷降级 |
| `strict-aon-v1` | 同一共享容量 | 全部成交或整笔拒绝 | 同上 | 不支持；另有部分成交政策差异 |
| `native-parity-v1`（显式选择） | 同一共享容量 | 部分成交，余量取消 | 原生百分比价、涨跌停价裁剪、无 tick 取整，分项费用不取整；必须零过户费 | 固定原生 worker 的声明配置支持；实际输出仍逐项审核 |

“原生兼容”是研究另一套明确假设，不是认定它比保守规则更准确，更不是将有分歧的旧报告修改成一致。默认保守规则不换成原生宽松规则。请求原生不具备的费用、tick 或整笔成交政策时，返回 `UNSUPPORTED_CONTRACT`，且不启动原生进程。

费用参数继续为明确确认的演示参数；没有将某一演示费率说成现行券商报价。金额计算使用 Decimal。原生对照保留原始浮点观察，以固定绝对容差 `0.000001` 核对；不先把原生观察四舍五入成期望结果。浮点极端数值无法满足合同会拒绝验收，不自动扩大容差。

## 2. 共享成交容量和订单生命周期

每个声明日期只有一个开盘代理撮合会话。首次订单开始时读取该日声明容量，按输入数组顺序处理意图。每次只扣除实际成交量，买入和卖出共用同一份容量，卖出不释放容量，失败/取消不占用容量；下一日重新建立容量。按 100 股步长确定可成交量，不足一手的剩余容量保持可见但不可使用。

每个意图最多一笔成交，余单立即取消，不跨天挂单，不在收盘再次撮合。满额现金和可卖数量按原始申请量检查，不因为流动性不足而自动缩小申请量来绕过资金/T+1检查。新参考实现不复用原 `execute_order`。

新参考执行器还拒绝会因卖出费用导致透支的操作。原生结果必须通过非负现金/持仓及完整账本检查；原生执行成功不代表该结果自动满足所有合同不变量。

容量明细包含：意图 ID、日期、证券、会话总容量、之前已用、本次实际成交、之后已用、剩余容量和取消股数。原生一侧的容量明细从观察到的成交推导，不冒充原生匹配器内部遥测。

## 3. 规则、输入与实现身份

`prepare_request(case, profile)` 产生新的 v2 请求，保留完整 v1 合成 case 和原始数据声明身份。规则的名称、schema 和全部规则内容共同计算 ID，整个请求再计算独立 ID。因此同一行情与订单换用不同规则，会产生不同研究身份。

规则注册表返回副本，调用者不能修改全局默认值。未知版本、未知字段、擅自改规则、修改后自行重算哈希、将真实数据重标为实验输入、重复订单、非有限数字和非整手意图均不能通过校验。传入的数据身份仍是声明；请求哈希不证明数据许可或市场事实真实。

原 RQAlpha worker、原 Invest 引擎和 v1 比较器源码保持不变；新模块位于 `integrations/execution_contract`，不修改原工作台 Python 核心身份。原生绑定固定 worker SHA-256、原生源码 commit 和 151 个 Python 文件身份，并在实际运行后核对原生配置。改变 worker 需要重新设计和验证绑定，不接受仅沿用旧合同名。

原生进程仍只接收同一合成行情和下单意图，不接收参考成交、余额或净值。新参考实现与原生撮合没有共享成交代码；规则审计器本身不是第三套独立引擎，也不是独立人工审稿。

## 4. 如何运行

无需重新下载已归档的 RQAlpha 源码。可复用已有独立环境，或按原 `tools/setup_engine_lab.py` 使用 Drive `Github/03_Invest_量化投资` 中的固定源码 ZIP 建立新环境。第三方实际许可仍须阅读并确认；源码许可与金融数据许可相互独立。

```powershell
python tools/run_execution_contract.py --rqalpha-python D:\Invest-RQAlpha\Scripts\python.exe --acknowledge-rqalpha-license --output D:\Invest-Results\contract-run-001
```

输出父目录须已存在，结果目录须不存在。运行结束后打开 `index.html`，或读取 `summary.json`、`protocol.json`、`cases/*.json`、`robustness/*.json`。`SHA256SUMS.json` 覆盖结果文件。HTML 是离线静态报告，无外部资源；只有看报告不需要 Python。

Python API：

```python
from integrations.execution_contract import model
request = model.prepare_request(validated_synthetic_case)  # 保守部分成交
reference = model.run_reference(request)
model.audit_result(request, reference)
# 原生兼容必须显式另建请求；不能把 strict 请求偷偷改成 native。
```

完整回归：`python -m pytest -q` 或 `python -m unittest discover -s tests -v`。

## 5. 验证覆盖与不可混淆的计数

当前预声明矩阵为 33 个场景 × 3 个规则版本，共 99 个组合。每组保留结果或拒绝理由，检查成交量有独立手工指定的金样本；不能因为两边都没有成交而判定正确。

本地实际结果：32 组原生对照 MATCH，66 组保守合同原生不支持（参考执行通过，但没有伪造原生运行），1 组零过户费合同下的非零过户费请求拒绝，0 意外运行错误。新套件还有 8 组后续日期价格扰动、重复运行及网络拦截探测。

原来的 24 组 v1 对照重新执行，仍为 18 MATCH / 6 DIVERGED；16 组旧未来日期扰动保留。全仓库单元回归为 370 项测试、290 个子测试，新增 58 项；没有删除原测试或降低其标准。

新增反例覆盖：同日多策略重复占用容量、买卖共用容量、跨日重置、拒单不占用、部分成交后的不足一手余量、最低佣金、现金不足不自动缩单、T+1、价格 tick 与 OHLC、零过户费边界、身份篡改、伪造空成交、账本一致却少成交、规则不支持时夹带执行结果、变更 worker 却复用旧绑定。

本地初次原生环境缺 pandas，补齐容器已有依赖路径后运行；这是复用环境，不声称干净安装。本地 Chromium 被管理员策略阻止读取 file URL，不声称本地浏览器通过。干净 Windows/Linux 和真实浏览器以本次 exact-source CI 记录为准，不借旧 run 替代。
