# 样本外与 Forward-Paper 评价协议 v1

状态：**FROZEN_METHOD_V1**  
冻结日期：2026-09-23  
适用范围：Invest v0.1 及后续沿用本协议的 A 股研究实验。  
重要边界：本文件冻结的是**评价方法**，不是任何策略收益结论。当前尚未绑定首个授权真实数据集，尚未打开冻结留出集，也尚未产生 forward-paper 证据。

## 1. 为什么先冻结协议

在查看样本外结果之前先固定评价规则，避免把已经看过的数据重新称为“未见数据”，也避免因为一次结果不好看就临时更换指标、成本、基准或时间边界。合成数据、单元测试、CI 通过只证明软件行为，不构成收益证据。

协议 v1 一旦进入 GitHub 历史，不原位改写其含义。需要改变方法时新增 v2，并保留 v1 及其已绑定数据/结果记录。

## 2. 数据准入门

任何真实市场评价开始前，必须先建立不可含糊的数据绑定记录，至少包括：

- 数据来源、授权/许可状态、获取时间与原始文件或快照身份；
- 证券范围与纳入/排除规则；
- 交易日历、时区、价格单位、成交量单位和复权口径；
- 停牌、涨跌停、公司行动、风险警示、退市/更名及缺失字段的覆盖情况；
- 是否存在存活偏差、回看偏差或无法证明 PIT（point-in-time）的字段；
- 原始输入哈希、规范化数据指纹和代码版本。

关键状态未知时保持未知并阻断需要这些状态的回测，不以 `false`、`0` 或前值填充伪装为已验证。

## 3. 四阶段评价边界

### A. Development

- 可调试代码、修正数据问题、提出与淘汰假设。
- 同时活跃的主要假设族默认不超过 3 类。
- 每个假设族默认最多记录 20 个独立参数配置；超过预算必须先登记原因并发布新协议版本或独立实验注册，不得静默扩大搜索。
- 所有失败、拒单、无效假设和调参尝试同样登记。

### B. Validation

进入前必须固定候选、参数、数据边界、成本情景、基准和指标。

- 最多 3 个候选进入同一次 validation。
- 第一次读取 validation 结果后，不再依据该结果修改候选参数并继续声称同一 validation 未见。
- 若修改逻辑或参数，需要回到 development，并登记新的 validation 身份。

### C. Frozen Holdout

- holdout 的起止日期、数据身份和候选参数必须在首次读取结果前登记。
- 同一 holdout 对一个已冻结候选只允许一次“首次观察”语义。
- 首次观察后若修改信号、参数、执行、费用、证券池、数据清洗或指标定义，该 holdout 视为已见，不能继续作为该新版本的 unseen 证据。
- 需要再次评价时必须登记新的、此前未打开的 holdout 或转入 forward-paper。

### D. Forward-Paper

- 只记录当时可见的信息；信号、候选动作、理由和撤销条件必须在结果可知之前写入不可回溯的时间记录。
- 不允许事后补写成功信号、删除失败信号或回改旧决策使其“看起来更好”。
- 数据延迟、缺失、不可成交、停牌和未知公司行动均保留为真实运行状态。
- 至少积累 60 个交易日且至少 20 个可评价决策事件，才允许形成“运行稳定性”阶段总结；达到该数量本身仍不能证明盈利能力。

## 4. 时间切分与首次数据绑定

v1 不在没有真实授权数据时虚构具体日期。首个真实评价数据到位后，必须在读取 holdout 结果之前新增 `evaluation_run`/binding 记录，明确：

1. development 日期区间；
2. validation 日期区间；
3. frozen holdout 日期区间；
4. 至少 3 个需要覆盖或单独标注的历史市场环境；
5. 证券池形成规则及其 PIT 证据；
6. 首次观察时间。

时间段必须按时间单向前进且不重叠。任何无法证明当时可见性的特征不得进入历史决策。

## 5. 固定比较框架

每个正式历史评价至少同时保存：

- 策略净值与同区间简单基准；
- 相同数据身份和相容的费用/成交假设；
- 至少 3 组明确命名的成本情景（例如 low/base/high；具体数值由实验注册冻结，不在本协议伪装成永久真实历史费率）；
- 总收益、基准差、最大回撤、换手、交易次数、成本总额与拒单/不可成交统计；
- 数据缺失与阻断原因；
- 若样本长度足够，可报告年化波动等辅助指标，但不得用单个风险调整指标替代完整证据。

胜率、单次最佳收益或某个参数的最高收益只能作为诊断项，不能单独构成升级或推荐依据。

## 6. 泄漏与可交易性检查

任何正式评价都必须检查：

- 信号只使用信号时点以前可见的数据；
- 信号日与最早可成交日分离；
- 未来价格变化不能改写过去结果；
- 证券池、财务/公告字段和风险状态满足 PIT 要求；
- 缺交易日历、未知停牌/限价/公司行动时继续 fail closed；
- 回测关键交易与独立账本或可人工复算记录一致。

发现未来信息泄漏、数据身份漂移、存活偏差无法解释或不真实成交时，该评价标记 INVALID，不做收益解释。

## 7. 结果解释与升级门

只有同时满足以下条件，才允许把 frozen holdout 结果作为研究证据讨论：

- 数据绑定和身份检查通过；
- 开发/验证/留出边界在首次读取前已冻结；
- 成本、基准和执行约束未在看结果后改写；
- 无已知未处理泄漏；
- 失败实验与搜索预算可追溯。

即使通过，也只能说明“该冻结样本上的观察结果”，不得外推为未来收益承诺。进入持续 forward-paper 需要另行满足数据更新可靠、决策日志可追溯等条件。

## 8. 变更控制

- v1 文件保留历史，不为适配结果而原位改写关键规则。
- 任何会改变结论含义的规则变化创建 v2，并说明为什么改、影响哪些旧实验、哪些数据已被看过。
- 纯错别字或不改变语义的说明修订，也应在决策/验证记录中可追溯。
- `docs/EVALUATION_LEDGER.md` 记录每次正式评价；机器可读状态在 `governance/evaluation_protocol_v1.json` 和后续 run/binding manifest 中保存。
