## 3. 开始使用

安装 Python 3.11 或以上版本后，在源码根目录运行：

```powershell
python -m invest --data-dir D:\Invest-Data --open
```

默认只监听本机 `127.0.0.1:8765`。不需要美元账户、GPU、云服务或模型 API。核心使用 Python 标准库；AKShare 是可选依赖，安装与数据访问需自己的网络条件。

```powershell
python -m pip install -e ".[market]"
```

这沿用研究线固定的 AKShare 版本，不承诺其上游服务长期可用。接口失败保持可见，不自动用合成数据代替。Tushare 仍只从服务器环境变量读取凭据，不在网页收集 Token。

有经本轮 CI 构建并验证的 Windows 便携包时，以包内 `SOURCE_COMMIT.txt` 和 `PACKAGE_MANIFEST.json` 为准。2026-09-25 的旧 EXE 不包含这次的新代码，不得当作新版本分发。

## 4. G1 数据路径

新首页可以载入合成演示或选择已有数据。真实 CSV 和在线导入继续使用原版数据管理界面。数据回执记录数据ID、来源、价格和成交量口径、规范化大小、代码内容身份以及每个标的的执行窗口检查。

`UNKNOWN` 是有效的“未知”状态，不是通过。回执会重新验证执行窗口，因此即使缓存审计被改成通过，也不会绕过缺失交易事实。原始文本可通过 API 提交并得到 SHA256；没有原始文本时显示空值，不编造原文件身份。提供文本哈希不代表完成了原始文件与行情的同源校验。

## 5. G2 实验协议

默认候选为 MA 5/20 和 MA 10/30，属于一个可解释思想族。允许1–3个候选，名称不得重复。所有候选先按最大慢均线长度取得共同预热，余下样本顺序划为三个不重叠评价区间，每区至少约10个交易日。

每一候选在每一区间分别运行低、中、高三种**固定演示成本**。这些参数不是券商报价，也不是历史法定费率的自动还原。每次必须由用户勾选确认。策略使用截至前一交易日收盘的信息，在下一交易日开盘尝试成交，继续继承原引擎的日线约束和拒绝执行逻辑。

每项结果保存完整参数、日期、现金基准、买入持有基准、交易、拒单、曲线和警告。不对候选自动排名或挑选“最佳”。失败项保存原因；落后买入持有的结果不被隐藏。数据和业务结果相同的研究文档按内容去重，保存时间在外层记录，不污染业务身份。

独立回放不调用 `execute_order`，重新计算成交额、分项费用、现金和持仓，并核对每个评价日的策略净值和基准净值。它证明算术一致性，不证明成交价现实可得，也不构成第二来源数据或独立市场引擎。

此接口不接收 `holdout_open` 等字段，不能打开原有冻结留出集。真实留出仍需要原有 `evaluation.py`、`provider_validation.py`、`opening.py` 的证据链，并在独立授权和协议下执行。

## 6. G3 账本语义

### 两种用途明确区分

- `/legacy` 的 `PaperLedger`：沿用已声明完整行情的历史模拟成交模型。
- 新复盘页：人工声明事件的会计复盘，模式固定为 `MANUAL_REPLAY_NO_EXECUTION_CLAIM`。不把人工填入的成交价格当成市场验证结果。

初始现金为人民币，最多精确到分。支持的事件如下：

| 事件 | 附加字段 | 含义 |
|---|---|---|
| DEPOSIT / WITHDRAWAL | amount | 外部现金流，不计为投资利润 |
| BUY / SELL | symbol, quantity, price, fee | 人工买卖声明；非自动撮合 |
| DIVIDEND | symbol, amount | 已确认税后现金总额，须有对应持仓 |
| FEE | amount | 其他人工确认费用 |
| MARK | prices | 必须且只能包含所有当前持仓的完整估值 |
| DECISION | reason, evidence_at | 记录理由与当时可见的证据时间 |
| FAILURE / RETRY | reason | 保留运行/研究异常和重试说明，不移动资金 |

每个事件必须带有有时区的 `occurred_at` 和证据来源。事件按时间追加；不支持覆盖、删除或倒序修订。发现历史错误时保留原账本，另建更正复盘账户。服务器另外生成 `recorded_at`，不能用历史事件时间冒充实际记录时间。

买入100股整数倍；同一沪深日期买入的库存不能当天卖出；不足现金、做空、模糊币种、非有限值、额外未支持字段均拒绝。人工事件不是完整交易所规则的替代，更不核验账户准入、流动性或实际税务。

### 现金流与收益

现金账本使用 Decimal。持仓成交后必须提交 MARK；成交价不会自动变为当前估值。缺估值时净资产与收益为空，不能用0或成本价掩盖。

复盘单位化以初始现金对应单位数、初始单位净值1开始。外部存取款前，如有持仓，须有**同一时刻**的完整估值。按流入/流出金额除以该时点单位净值增减单位数，避免把入金当利润。全额退出到零资产不延续旧收益率，需新建账户。

利润口径为“按末次价格的净资产 − 初始现金 − 外部净现金流”。时间加权收益只在完整、同一时点估值时输出。最大回撤只针对已观测的单位净值，不声称覆盖未记录的市场波动。持仓价格超过24个自然小时会提示过期；这是数据年龄提示，不猜测交易所是否开市。

### 幂等与并发

事件幂等键在单个复盘账户内唯一：相同键和相同规范化内容返回原事件；相同键换内容拒绝。SQLite `BEGIN IMMEDIATE` 包住读取、重放验证及追加，防止两个请求同时花掉同一余额。

事件哈希包含账户ID、序号、幂等键、规范化内容、前一事件哈希及服务器记录时间。每次读取重新验证整条链。数据库追加约束防止普通更新删除，但哈希链并不是对掌握整台机器的攻击者的外部可信时间戳；没有声称硬件签名或第三方见证。

## 7. G4 档案与恢复

实验、回执、复盘配置和事实包保存在现有 `state.sqlite` 的新增表中；新复盘事件也在同一数据库。原版模拟账户和笔记继续在 `paper.sqlite`。数据库升级只增加新表和约束，不删除旧数据。

完整备份使用 SQLite 在线备份 API，不直接复制正在写入的 WAL 文件。用户必须明确同意导出含私人账本的 ZIP。ZIP 提供清单与 SHA256，并可通过 `restore_backup.py` 恢复：

```powershell
python restore_backup.py Invest-complete-private-backup.zip D:\Invest-Restored
python -m invest --data-dir D:\Invest-Restored --open
```

目标父目录须存在，目标目录本身不能存在。恢复校验路径白名单、重复文件、解压大小、哈希和数据库完整性，绝不覆盖当前工作区。

研究单文档 JSON 导出和完整私人备份用途不同：单文档不代表完整状态；完整备份可能包含持仓/笔记/原文，不自动上传到 Drive、GitHub 或任何模型服务。交付验证中的备份只有合成测试内容。

## 8. G5 本地时点事实包

扩展默认关闭，且不是原引擎的输入依赖。每包提供 `source_name`、`source_text`、`license_note` 和 facts 数组。来源文本会记录 SHA256，但依然属于用户声明，来源真实性和许可未独立核验。

每条事实必须具备 symbol、metric、period_end、available_at、revision、value、unit。修订号递增时可见时间必须严格递增，同一指标和报告期不能偷偷改单位，也不能有相同修订号的两份内容。数值须有限，证券范围沿用主板研究范围。

查询时先按可见时刻过滤，再选每个指标和报告期当时最新的修订。不会因为后来出现修订，就在过去的查询里替换旧值。不同时间偏移表示同一瞬间时，返回一致结果。

扩展没有自动财报抓取、自然语言公告解析、ETF适配或交易联动。它提供的是一条可独立关闭、可版本化、可隔离评测的研究扩展轴，而不是所有可能的G5扩张方向。

## 9. 验证方法与结果边界

在本轮工作容器中，桌面发布源码的125个原测试先通过；补齐模块后新增独立测试和HTTP集成测试，本地共224项通过，并执行源码编译和JavaScript语法检查。该本地快照基于已发布桌面源码再同步本轮用到的研究线模块；研究线独有的其余测试保留在GitHub基线，远程展开后必须再跑完整集合。**以本轮远程日志中的真实数量为最终完整集合数量，不把224冒充远程数量。**

工作容器内 Chromium 拒绝访问本机网页，因此该环境没有完成真实浏览器页面验收。`tools/growth_browser_test.py` 提供真实回环HTTP浏览器流程；Windows打包测试使用实际EXE，并检查合成研究、股息费用估值11103元、事实修订过滤、扩展关闭、下载、重启和390px布局。只有这些步骤实际运行成功才记为通过；未运行或失败保留原状态。

验收证据至少区分：单元测试、HTTP测试、浏览器、已编译EXE、用户Windows设备、真实数据/真实研究。一个层面的通过不能替代另一个层面。

## 10. 当前不能关闭的验收项

1. 获得并核实足以研究的真实数据、使用依据、时间身份和市场执行事实。
2. 将三个真实市场环境、独立成交引擎对照和严格样本外验证绑定到真实输入；开放冻结留出须按原协议。
3. 积累真实后续信息下的持续模拟记录，保留缺失、重试、失败和假设被否定的证据。
4. 验证用户设备的安装、输入法、文件权限、浏览器和备份恢复；开展真实可用性观察和独立审阅。
5. 依据实际重复使用价值决定是否把PIT扩展投入研究，不因存在模块就认定已证明用户收益。

这些项目不是旧的安全规则残留，也不是借口停止开发，而是尚未取得的事实证据。本次已经把不依赖这些事实的可运行工程能力做好，并保留以后能接续的接口、测试与状态。
